# Spiral Bloom

openFrameworks で書かれた [mutek_archive](https://github.com/sw-sw-sw/mutek_archive) のパーティクルビジュアル(`ofApp.cpp` / `particle.cpp`)を、そのまま WebGL2 に移植した単一 HTML ファイル。ビルド不要・依存ライブラリなしで、`spiral-bloom.html` をブラウザで開くだけで動作します。MUTEK のライブで使われた元コードの数式をそのまま再現しつつ、右サイドパネルから全パラメータをリアルタイムに操作できます。

## 使い方

### 起動

```bash
open spiral-bloom.html
```

もしくは任意の静的サーバーで配信してください(例: `python3 -m http.server` → `http://localhost:8000/spiral-bloom.html`)。WebGL2 に対応したブラウザ(最新の Chrome / Edge / Firefox / Safari)が必要です。

### 画面構成

- **キャンバス全体**: パーティクル(最大100万個)が描画されるステージ。背景は毎フレーム完全にクリアされず、`Decay` の値だけ黒を薄く重ねる方式でトレイル(残像)を出しています。
- **左下 HUD**: `particles`(現在の描画数)/ `fps` / `resonance`(共鳴度、後述)/ `LIVE` インジケータ。
- **右サイドパネル**: 全パラメータのスライダー。パネル左端の `›` タブをクリックすると開閉できます。

## コントロール一覧

パネルのラベル下に小さく表示されているコードは、元の openFrameworks コード(`ofApp.h` / `ofApp.cpp`)の変数名・OSC アドレスとそのまま対応しています。

### Form(形状)

| ラベル | コード | 内容 |
|---|---|---|
| Count | `num` | 描画するパーティクル数(1,000〜1,000,000)。多いほど密度の高いテクスチャになるが GPU 負荷も増える |
| Spread | `r` | 螺旋の半径(外周までの距離) |
| Spin | `fff` | 角度の倍率。1個進むごとに何回転分ずれるかを決める(腕の巻き数) |
| Wind | `posr` | 角度の分母。`Spin` と組み合わせて巻きつきの密度を微調整する、"共鳴"を探す主軸 |
| Scatter | `fase` | 各パーティクルにかかるノイズ(粒状のゆらぎ)の強さ |
| Depth | `depth` | 奥行き方向の周期運動の強さ(擬似3D的な明滅) |

### Motion(動き)

| ラベル | コード | 内容 |
|---|---|---|
| Glide | `a` | 全パラメータが目標値に近づく速さ(指数平滑のレート)。小さいほどゆったり、大きいほど機敏に反応する |
| Rotate | `rot` | 画面全体が1フレームあたり何度回転するか |
| Pulse speed | `lfo` | Scatter を揺らす LFO の速さ |
| Pulse depth | `lfo_d` | LFO がどれだけ Scatter を押し上げるか(揺らぎの深さ) |

### Light(光)

| ラベル | コード | 内容 |
|---|---|---|
| Glow | `alpha` | 点の明るさ(加算合成のため、上げすぎると重なった部分が白飛びする) |
| Decay | `fade` | トレイルの消え方。小さいほど残像が長く伸び、大きいほどキレのある表示になる |
| Size | `size` | 点の描画サイズ(px) |

### プリセット

- **Original** — `ofApp.h` に書かれていた実際のデフォルト値(`fff=3.782047`, `posr=0.433071` など)。ライブで実際に使われていた設定そのもの
- **Bloom** — `posr=0.5`, `fff=6.912` として意図的に 5-fold(5枚花びら)の共鳴点に合わせ、Scatter を下げてクリーンなロゼット状にしたプリセット
- **Drift** — Original と同じ角度比率のまま Scatter・Depth を上げ、より複雑でノイジーな状態に振ったプリセット

### Scan for resonance

`posr` または `fff` を 0.001 刻みで走査し、「今の巻き角度が単純な分数(分母24以下)にどれだけ近いか」を連分数展開で判定して、綺麗な花びら状になるポイントを自動的に探すツールです。

1. 走査する軸(`posr` か `fff`)を選ぶ
2. **Run scan** を押すと、誤差が小さい上位18箇所がボタン化される
3. ボタンをクリックするとその値へ即座にジャンプし、他のパラメータはそのまま維持される

各ボタンには推定される花びら数(`n-fold`)とその軸の値が表示されます。HUD の `resonance` 表示は、現在の `fff/posr` がどれだけ整った比率に近いかを常時判定していて、`n-fold · locked`(整っている)/ `≈ n-fold · drifting`(近いが少しずれている)/ `diffuse`(単純な比率から遠い)の3段階で表示されます。

## アルゴリズム 

元コード `particle.cpp` の核心はこの数行。

```cpp
float rate = (float)*p_counter / (float)*p_NUM;          // 0〜1、自分の index が全体の何割目か
posR = (*p_counter % 36000) / *p_posr;                    // 「角度」の元になる値

pos->x = sin(posR * *p_fff) * (*p_R) * rate + sin(*p_counter) * *p_fase;
pos->y = cos(posR * *p_fff) * (*p_R) * rate + cos(*p_counter) * *p_fase;
```

各パーティクルは「自分の連番 `i`(counter)」以外に何の状態も持たず、`i` だけから自分の位置を毎フレーム計算し直しています。この単純さの中に、複数の異なる原理が積み重なって「オーガニックに見える」現象を生んでいます。

### 1. 骨格はスピログラフ / バラ曲線(rose curve)

- `rate = i / NUM` によって、index が若いほど中心近く、大きいほど外周に配置される → 半径が index に比例する
- `posR * fff` は「1個進むごとに固定の角度だけ回転する」という円周上の回転写像(rotation map)。角度のステップ幅は `fff / posr`

この2つを組み合わせると、パーティクルの集合は中心から外側へ向かって渦を巻く螺旋(アルキメデスの螺旋の発展形)になり、`fff` の値が大きいほど1周の間に何度も巻きつく多重螺旋(バラ曲線)になります。

### 2. カオスではない生命性現象

ロジスティック写像 `x_{n+1} = r・x_n・(1-x_n)` のようなカオス系は、**前の状態を非線形にフィードバックする反復**によって、初期値のわずかな差が指数的に発散する(バタフライ効果)という性質を持ちます。

このコードにはそのフィードバック構造がありません。各パーティクルの位置は自分の `i` だけから直接計算される非再帰的な関数で、隣接する index 同士は常に同じ角度差を保ち続けます。これは力学系の用語でいう **「円周上の回転写像(irrational rotation)」** そのもので、初期値鋭敏性はゼロ、リアプノフ指数もゼロです。数学的にはむしろカオスの教科書的な"対照例"として扱われる仕組みです。

### 3. Weyl の等分布定理

角度のステップ幅を `α = (fff / posr) / 2π`(1周に対する割合)とすると:

- **`α` が単純な分数 `p/q` に近い** → 点は `q` 個の決まった角度スロットにしか落ちない → **`q` 枚花びらの整った模様**になる(まさにスピログラフで歯車比が単純な整数比のとき星形が綺麗に閉じるのと同じ)
- **`α` が単純な分数から遠い(無理数的)** → 点は円周上にほぼ一様にばらまかれる(数学的に「等分布」する)→ 見た目は**ノイズ**になる

パラメータ空間のほとんどは後者(無理数的)に該当するため、感覚的に探ると大半がノイズに見え、ごく狭い"共鳴"領域でだけ規則的な花びらが現れます。これは前述の `Scan for resonance` 機能が探しているものと同じ現象。

### 4. "秩序とノイズの境界"(edge of chaos)

共鳴が強すぎる(単純すぎる比率、`q` が小さい)と模様は単調で退屈になり、共鳴が弱すぎる(無理数的)と完全なノイズになります。複雑系科学でいう **edge of chaos** — 秩序でも純粋なカオスでもない、その境界の狭い帯域で複雑さ・生命感が最大化するという考え方 — が、このパラメータ空間にもそのまま当てはまります。`Scatter` を上げて意図的にノイズを混ぜているのも、この"境界"を人為的に作り出す操作。

### 5. オーガニック性

数式の骨格そのものとは別に、以下の実装上の工夫が「生命感」を底上げしています。

- **指数平滑(easing)によるすべての追従** — `Count`・`Spread`・`Scatter`・`Depth` は目標値に瞬間移動せず、`value += -(value - target) * Glide` という減衰カーブで滑らかに近づく。生物の筋肉や呼吸のように、慣性を持って目標に漸近する動き
- **マクロな秩序 + ミクロな不規則性の共存** — 螺旋という大域的な秩序の上に、`sin(i) * fase` という独立したノイズ成分を重ねている。木の枝分かれや波打ち際のように、「完全に規則的」でも「完全にランダム」でもない中間状態が自然物らしく見える
- **非同期な位相** — 各パーティクルは初期化時にランダムな奥行き位相(`z_depth`)を持ち、それぞれ独立してループする。心拍や群れの動きのように、全体が完全に同期しないことが機械的な印象を避けている
- **LFO による低周波の"呼吸"** — `Pulse speed` / `Pulse depth` が `Scatter` の強さ自体をゆっくり揺らすことで、画面全体が呼吸するように明滅する

### 6. 自然界・装飾芸術との数学的な相似性

「中心のまわりに角度を蓄積させながら点を配置する」というこの1つの操作は、スケールを問わず自然界や伝統文様に繰り返し現れます。

- **花(フィロタキシス)** — ひまわりの種の配置(Vogel モデル: `θ_n = n × 黄金角`, `r_n = c√n`)と構造的に同一
- **渦巻銀河** — 中心に近い星ほど速く公転する差動回転によって腕が対数螺旋状に巻き込まれる現象(密度波理論)と比喩的に対応
- **曼荼羅** — `fff/posr` が単純な有理数 `p/q` に近いときに現れる `q` 回対称は、曼荼羅の回転対称性(円の等分割)と数学的に同じ操作

## 元コードとの対応

| このツール | 元の openFrameworks コード |
|---|---|
| `spiral-bloom.html` の頂点シェーダー | [`particle.cpp`](https://github.com/sw-sw-sw/mutek_archive/blob/master/mutek_oF/src/particle.cpp) `Particle::update()` |
| Form / Motion / Light の各パラメータ | [`ofApp.h`](https://github.com/sw-sw-sw/mutek_archive/blob/master/mutek_oF/src/ofApp.h) のメンバ変数、[`ofApp.cpp`](https://github.com/sw-sw-sw/mutek_archive/blob/master/mutek_oF/src/ofApp.cpp) の OSC ハンドラ(`/NUM`, `/R`, `/fase`, `/fff`, `/posr`, `/depth`, `/lfo` など) |
| トレイル(Decay) | `ofSetBackgroundAuto(false)` + 毎フレームの半透明矩形描画 |

元のプロジェクトは openFrameworks + `ofxOsc`(OSC 受信)+ `ofxSyphon`(映像出力)で構成され、外部コントローラから OSC でパラメータを操作する前提で書かれていました。このツールはその OSC 入力をブラウザのスライダーに置き換えたもの。
